An interactive, safe visualization of a classic stack-frame buffer overflow. Type a string, run a vulnerable strcpy(), and watch what happens to the buffer, the saved frame pointer, and the return address. No real exploit — just the concept.

The vulnerable C program

// greet() copies user input into a fixed-size buffer.
// strcpy() does NOT check the destination size!
void greet(const char *input) {
    char buffer[16];
    strcpy(buffer, input);  // ← the bug
    printf("Hello, %s!\n", buffer);
}  // ← on return, CPU jumps to the saved return address

📖 What just happened?

When greet() is called, the CPU pushes a return address onto the stack so it knows where to continue in main() afterwards. Then it saves the caller's frame pointer (EBP), and finally reserves 16 bytes for buffer at lower addresses.

strcpy() copies bytes one at a time — including the terminating NUL (00) byte — and never checks whether the destination has room. Input longer than 15 characters keeps writing upward: first into the saved EBP, then over the return address.

When the function later executes return, the CPU trusts whatever bytes now sit in the return-address slot and jumps there. In this lab that means a crash (SIGSEGV). In real historical attacks, those bytes were chosen to point at attacker-supplied code — which is why this bug class mattered so much.

🛡️ How is this prevented in the real world?
  • Bounds-checked functions: strncpy, snprintf, fgets — or memory-safe languages (Rust, Go, Python) that check bounds automatically.
  • Stack canaries: the compiler places a random value between locals and the saved registers and verifies it before returning (toggle it above!).
  • ASLR (Address Space Layout Randomization): memory layout changes every run, so attackers can't predict addresses.
  • NX bit / DEP: the stack is marked non-executable, so injected bytes can't run as code.
🕰️ Why should I care? A bit of history

The 1988 Morris Worm — one of the first internet worms — spread partly by overflowing the 512-byte buffer of the fingerd daemon, which used the unchecked gets(). Decades later, buffer overflows powered Code Red, Slammer, and countless CVEs. Understanding the stack frame is step one to understanding memory safety.
